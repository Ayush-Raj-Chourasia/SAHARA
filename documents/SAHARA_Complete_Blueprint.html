Full System Architecture

The complete data flow: Senior → AI Engine → Family Dashboard

Senior logs meal/vitals on mobile → FastAPI processes → ML scores risk → MongoDB stores → Family dashboard polls → Alert fires if risk HIGH → Twilio SMS to family phone

Layer 1 — Frontend

Senior App (React Native / Expo)
Screens: / Home → Health score + today summary /log → Log BP, sugar, Hb, weight /nutrition → Meal logging + AI analysis /sos → Emergency big red button /chat → SAHARA AI (voice + text) /reminders → Medication alerts
Family Dashboard (React Web)
Screens: / → Linked seniors list + risk badges /senior/:id → Deep dive: 7-day trend charts (Recharts) Risk alert timeline Medication compliance calendar SOS history + Google Maps pin Weekly AI-generated report

Layer 2 — Backend (FastAPI + Python)

POST /auth/register → create user (role: senior | family) POST /auth/login → JWT token (expires 7 days) POST /health/log → save vitals, run risk scoring → return {score, flags} GET /health/history/:id → last 30 days for charts POST /nutrition/analyze → Gemini parses meal text → return macros + deficit GET /nutrition/today/:id → today intake vs elderly targets POST /emergency/sos → Twilio SMS + save GPS event + FCM push GET /family/dashboard/:id → aggregated health + risk + trends POST /ai/chat → Gemini with health context injected

Layer 3 — Database (MongoDB Atlas)

Collection: users { _id, name, age, gender, role, phone, weight_kg, conditions[], linked_family[] } Collection: health_logs { user_id, timestamp, bp_sys, bp_dia, blood_sugar, hb, weight, health_score, risk_flags[] } Collection: nutrition_logs { user_id, timestamp, meal_text, gemini_response{calories,protein_g,iron_mg}, deficit{} } Collection: reminders { user_id, medicine_name, time_scheduled, taken: bool, taken_at } Collection: sos_events { user_id, timestamp, latitude, longitude, resolved: bool, sms_sent: bool } Collection: family_links { family_id, senior_id, relationship, notify_on_risk: bool }

Layer 4 — AI/ML Engine

Custom models (Python)
  • anaemia_risk_model.pkl — Random Forest on Hb, age, gender, iron intake
  • health_score_engine.py — Weighted rule engine (0-100 score)
  • anomaly_detector.py — Isolation Forest on 14-day BP/sugar trend
LLM integrations
  • Gemini 1.5 Flash — nutrition parser (JSON output)
  • Gemini 1.5 Flash — health chatbot (Hindi/English)
  • Gemini 1.5 Flash — weekly health summary generation

Layer 5 — External Services

Twilio

SOS SMS to family numbers. WhatsApp API as backup. Free: 1000 SMS/mo. Cost: ~₹1.50/SMS after that.

Google Maps JS API

Embed interactive map on SOS event page. Show last GPS coordinates. Free tier: 28,000 loads/mo.

Firebase Cloud Messaging

Push notification to family app when risk alert fires. Completely free. Instant delivery.

UX Design — Elderly-First, Every Decision Justified

Non-negotiable UX rules for elderly users

  • Font minimum: 18px body, 28px for vital numbers
  • Button height: minimum 56px — fat-finger safe
  • Max actions per screen: 3 — never overwhelm
  • Navigation: bottom tab bar only — no hamburger
  • Contrast: never gray-on-gray, always 4.5:1 minimum
  • Icons: always paired with text labels
  • Primary color: Orange #F97316 — warm, visible, Indian aesthetic
  • SOS button: visible in bottom tab on EVERY screen
  • Voice input: on every text field — speak don't type
  • Confirmation: always confirm before irreversible action
  • Errors: large red text, not small tooltips they'll miss
  • Offline: cache last data locally — works without WiFi

Complete AI/ML Layer — Primary + Every Backup

Model 1 — Nutrition Analysis (Most Unique Feature, Build First)

Primary: Google Gemini 1.5 Flash
System prompt: "You are a clinical nutritionist for elderly Indians aged 60-85. Analyze the described meal. Return ONLY valid JSON, no extra text: { 'calories': 480, 'protein_g': 14, 'iron_mg': 3.2, 'carbs_g': 68, 'fiber_g': 5, 'suggestion': 'Add 1 egg...' }" Daily targets (injected per user): protein_target = 0.8 * weight_kg iron_target = 8 (men) / 10 (women) calories_target = 1600-2000
Backup chain — in order
Backup 1: Groq + Llama 3.1 API: api.groq.com/openai/v1 Model: llama-3.1-8b-instant Free, 30 req/min Same prompt format Backup 2: ICMR Food Database Local JSON: 500 Indian foods Source: ICMR nutritional tables (public domain, govt validated) Fuzzy match on meal name Backup 3: Hardcoded common meals "dal rice" → {protein:14g, iron:3mg} "poha" → {protein:5g, iron:2mg} "chapati sabzi" → {protein:8g} Works 100%, zero API calls

Model 2 — Anaemia Risk Prediction

Primary: Random Forest (scikit-learn)
from sklearn.ensemble import RandomForestClassifier import pandas as pd # Features X = ['hb', 'age', 'gender_encoded', 'fatigue_level', 'dietary_iron', 'bp_systolic'] # Dataset: Kaggle anaemia CSV # + WHO anaemia clinical data # Training time: ~10 minutes # Output { 'risk': 'HIGH', 'confidence': 0.87, 'primary_factor': 'low_hb', 'recommendation': 'Consult doctor' }
Backup: WHO Clinical Rule Engine
def get_anaemia_risk(hb, gender, age): if gender == 'F': if hb < 10: return 'HIGH' if hb < 12: return 'MEDIUM' return 'LOW' else: # Male if hb < 11: return 'HIGH' if hb < 13: return 'MEDIUM' return 'LOW' # WHO thresholds — clinically accurate # Tell judges: "WHO-validated rules" # This is actually more defensible # than an ML model to medical judges

Model 3 — Multi-Parameter Health Score (0–100)

def calculate_health_score(log): score = 100 # Blood pressure if log.bp_sys > 140: score -= 15 if log.bp_sys > 160: score -= 10 if log.bp_dia > 90: score -= 8 # Blood sugar if log.sugar > 140: score -= 15 if log.sugar > 200: score -= 10 # Haemoglobin (anaemia) hb_min = 12 if gender == 'F' else 13 if log.hb < hb_min: score -= 20 if log.hb < hb_min - 2: score -= 10 # Weight change if abs(weight_change_7d) > 3: score -= 10 # Medication missed if missed_meds_today: score -= 5 return max(0, min(100, score)) # Thresholds: 80-100=Good 60-79=Fair <60=Poor
